## 1. はじめに

### 1.1 目的
自宅で行う筋力トレーニングとストレッチ・姿勢改善エクササイズを、iPhoneで手早く記録します。あわせて、次の内容を確認できるようにします。

- いつ、どの部位を鍛えたか（カレンダー・人体図）
- 各部位がいつ回復するか
- 消費カロリーと、続けてきた記録の推移（グラフ）

記録したデータは、iPhoneの「ショートカット」アプリを経由して「ヘルスケア」に送れるようにします。

### 1.2 PWAを採用する理由
PWA（Progressive Web App）は、Webの技術で作るアプリです。iPhoneのホーム画面に追加すると、通常のアプリと同じように起動でき、オフラインでも使えます。

| 観点 | PWAにする利点 |
|---|---|
| 開発環境 | Windowsだけで開発できる（Macは不要） |
| 費用 | Apple Developer Programへの登録（年会費）が不要。無料のホスティングサービスで公開できる |
| 配布・更新 | App Storeの審査や、Xcodeでのインストールが不要。サイトを更新すればアプリも更新される |
| 対応端末 | iPhone・iPad・PCのどれでも、ブラウザがあれば動く |

一方で、ネイティブアプリと比べて次の制約があります（詳細は「7. 制約事項」）。
- ヘルスケアへ直接書き込めない（ショートカット経由で送る）
- iCloudでの自動同期ができない（手動でバックアップする）
- Apple Watchアプリは作れない

### 1.3 基本方針
1. **入力は最小限にする**：部位・目的を選ぶだけで記録できます。具体的な種目の入力は任意です。
2. **サーバーを持たない**：データは端末内（ブラウザの保存領域）にだけ保存します。ログイン画面やデータベース用のサーバーは作りません。
3. **データを失わない工夫をする**：端末内にしかデータがないため、ファイルへの書き出し・読み込みによるバックアップと、バックアップを促す表示を必須とします。
4. **段階的に拡張できる作りにする**：重量・回数・セット数の入力や、クラウド同期は後から追加できるよう、最初からデータ構造に組み込んでおきます。

## 2. 用語定義

| 用語 | 意味 |
|---|---|
| PWA | ホーム画面に追加して、アプリのように使えるWebアプリ |
| カテゴリ | 記録時に選ぶ部位または目的。「筋トレ系」と「ケア系」に分かれる（3.2参照） |
| 種目 | 「腕立て伏せ」などの具体的なトレーニング。どれか1つのカテゴリに属する |
| セッション | 開始ボタンから終了ボタンまでの1回のトレーニング。1つのセッションで複数のカテゴリを記録できる |
| METs（メッツ） | 運動の強さを表す指標。安静時を1とする。消費カロリーの計算に使う |
| 回復予定時刻 | 部位が回復したとみなす時刻。最後に鍛えた時刻に回復目安時間を足して求める |
| ショートカット | iPhone標準の「ショートカット」アプリ。決まった操作を自動で実行できる。ヘルスケアへの書き込みに使う |
| バックアップファイル | アプリの全データを1つのファイル（JSON形式）にまとめたもの。復元に使う |

## 3. 機能要件

優先度：**Must**＝フェーズ1で必須／**Should**＝フェーズ1で可能なら実装／**Could**＝余裕があれば実装／**Future**＝将来対応

### 3.1 トレーニング記録機能

| ID | 要件 | 優先度 |
|---|---|---|
| F-REC-01 | ホーム画面の「開始」ボタンでセッションを開始し、経過時間を表示する | Must |
| F-REC-02 | セッション中またはセッション終了時に、実施したカテゴリを1つ以上選ぶ（複数選択可） | Must |
| F-REC-03 | カテゴリを選んだあと、実施した種目も任意で選べる（複数選択可、選ばなくても保存可） | Must |
| F-REC-04 | 「終了」ボタンでセッションを終了し、開始日時・終了日時・所要時間を保存する | Must |
| F-REC-05 | アプリを閉じたり端末を再起動したりしても、計測中のセッションが途切れない（開始時刻を端末内に保存しておき、再表示時に経過時間を計算し直す） | Must |
| F-REC-06 | 開始ボタンを押し忘れたときのために、日時と所要時間を手入力して後から記録できる | Must |
| F-REC-07 | 保存済みの記録を編集・削除できる | Must |
| F-REC-08 | 終了ボタンを押し忘れた場合に備え、アプリを開いたときに開始から3時間（設定で変更可）以上経過していれば「終了し忘れていませんか？」と表示し、終了時刻を指定して保存できるようにする | Should |
| F-REC-09 | 「前回と同じ内容」でカテゴリ・種目をまとめて選べる | Should |
| F-REC-10 | 1行メモ（体調など）を残せる | Should |
| F-REC-11 | 種目ごとに重量・回数・セット数を入力する（入力欄は設定でオン・オフを切り替え。データ構造はフェーズ1から用意しておく） | Future |

### 3.2 カテゴリ・種目マスタ

#### 3.2.1 カテゴリ（アプリにあらかじめ登録）
| 区分 | カテゴリ | 人体図で色を付ける部位 | 回復目安（初期値） | METs（初期値） |
|---|---|---|---|---|
| 筋トレ系 | 大胸筋 | 胸 | 72時間 | 5.0 |
| 筋トレ系 | 背中 | 広背筋・脊柱起立筋 | 72時間 | 5.0 |
| 筋トレ系 | 下半身 | 大腿四頭筋・ハムストリングス・臀部・ふくらはぎ | 72時間 | 5.0 |
| 筋トレ系 | 肩 | 三角筋 | 48時間 | 5.0 |
| 筋トレ系 | 腕 | 上腕二頭筋・上腕三頭筋 | 48時間 | 5.0 |
| 筋トレ系 | 腹筋 | 腹直筋・腹斜筋 | 24時間 | 3.8 |
| ケア系 | 反り腰 | 腹部（インナー）・腸腰筋・臀部 | 回復管理しない | 2.3 |
| ケア系 | 股関節 | 股関節まわり | 回復管理しない | 2.3 |
| ケア系 | スマホ首 | 首・僧帽筋上部 | 回復管理しない | 2.3 |
| ケア系 | 小顔 | 顔・首 | 回復管理しない | 2.3 |

- ケア系（ストレッチや姿勢改善が中心で、毎日行っても問題ないもの）は、人体図で「実施済み」として表示しますが、回復時間の管理は行いません。設定で回復管理をオンにすることもできます。
- 回復目安とMETsはカテゴリごとに設定画面で変更できます（F-SET-02）。
- 数値は一般的な目安です。医学的な正確さを保証するものではありません。

| カテゴリ | 種目（初期登録） |
|---|---|
| 大胸筋 | 腕立て伏せ、ワイドプッシュアップ、ダンベルプレス（床）、ダンベルフライ |
| 背中 | ワンハンドダンベルロウ、バックエクステンション、スーパーマン、チューブローイング |

| 腕 | ダンベルカール、ハンマーカール、フレンチプレス、ナロープッシュアップ、ベンチディップス（椅子） |

| F-MST-03 | 追加した種目を編集・削除できる。記録で使用済みの種目は、削除ではなく「非表示」にする（過去の記録を壊さないため） | Must |

### 3.3 人体図・回復状況の表示

| ID | 要件 | 優先度 |
|---|---|---|
| F-BODY-01 | 人体図（前面・背面）をホーム画面に表示し、部位ごとに状態を色分けする。状態は「疲労中（赤）」「回復中（黄）」「回復済み（灰または緑）」の3段階 | Must |
| F-BODY-02 | 部位をタップすると、最後に鍛えた日時、回復予定時刻、回復までの残り時間を表示する | Must |
| F-BODY-03 | 回復予定時刻 ＝ 最後に鍛えたセッションの終了時刻 ＋ 回復目安時間 ＋ 筋肉痛による補正（F-BODY-05） | Must |
| F-BODY-04 | セッションの詳細画面に、そのセッションで使った部位を人体図で表示する | Must |
| F-BODY-05 | 筋トレ系の部位を鍛えた翌日以降、アプリを開いたときにホーム画面で「筋肉痛はありますか？」とたずね、なし・軽い・強いの3段階で記録できるようにする。初期の補正値は、なし：±0時間、軽い：＋12時間、強い：＋24時間（設定で変更可） | Must |
| F-BODY-06 | 状態の判定ルール：鍛えてから回復目安時間の50%が経過するまでは「疲労中」、それ以降回復予定時刻までは「回復中」、回復予定時刻を過ぎたら「回復済み」 | Must |
| F-BODY-07 | 筋肉痛の確認をプッシュ通知で知らせる | Future |

### 3.4 消費カロリー

| ID | 要件 | 優先度 |
|---|---|---|
| F-CAL-01 | セッションごとの消費カロリーを推定して表示する | Must |
| F-CAL-02 | 計算式：消費カロリー（kcal）＝（METs − 1）× 体重（kg）× 所要時間（時間）× 1.05。安静時に消費する分（1 MET）を除いた「運動による消費カロリー」とし、ヘルスケアの「アクティブエネルギー」と同じ考え方にそろえる | Must |
| F-CAL-03 | METsの決め方：種目を選んだ場合はその種目のMETs、カテゴリだけの場合はカテゴリのMETsを使う。複数ある場合は単純平均をとる | Must |
| F-CAL-04 | 体重はプロフィールに手入力した値を使う。セッション保存時点の体重を記録に残し、あとで体重を変えても過去のカロリーは変わらないようにする | Must |
| F-CAL-05 | 推定値であることを画面上に明記する | Must |

### 3.5 カレンダー・履歴

| ID | 要件 | 優先度 |
|---|---|---|
| F-CALD-01 | 月表示のカレンダーで、トレーニングした日に印を付ける（カテゴリ区分に応じて色を変える） | Must |
| F-CALD-02 | 日付をタップすると、その日のセッション一覧（開始〜終了時刻、所要時間、カテゴリ、種目、消費カロリー）を表示する | Must |
| F-CALD-03 | ホーム画面に「昨日やったこと」（昨日がお休みの場合は「前回やったこと」）を簡単に表示する | Must |
| F-CALD-04 | 連続でトレーニングした日数や、今月のトレーニング日数を表示する | Should |

- 日をまたぐセッション（例：23時〜翌0時30分）は、**開始日時の日付**の記録として扱います。カレンダー、昨日やったこと、連続日数、グラフ（3.6）の集計はすべてこの原則に従います。
- 回復予定時刻（3.3）は、これまでどおり終了時刻をもとに計算します。

### 3.7 ヘルスケア連携（ショートカット経由）

Webアプリはヘルスケアに直接書き込めません。そこで、iPhoneの「ショートカット」アプリにワークアウトを記録させる方式をとります。

**連携の流れ**
1. アプリでセッションを保存する
2. 「ヘルスケアに送る」ボタンを押す
3. ショートカットアプリが起動し、アプリから受け取った内容（開始日時・所要時間・消費カロリー・種類）でワークアウトを記録する
4. 自動でアプリに戻る（戻らない場合は手動で戻る）

| ID | 要件 | 優先度 |
|---|---|---|
| F-HLT-01 | セッションの保存後に「ヘルスケアに送る」ボタンを表示する。押すと、ワークアウトの内容を渡してショートカットを起動する | Must |
| F-HLT-02 | 送る内容：開始日時、所要時間、消費カロリー（アクティブエネルギー）、ワークアウトの種類。種類は、筋トレ系を含むセッションなら「筋力トレーニング」、ケア系だけのセッションなら「柔軟運動」 | Must |
| F-HLT-03 | セッションごとに「ヘルスケアに送信済み」の印を記録し、送り忘れているセッションがわかるようにする。送信済みのセッションは、送信済みであることを示したうえで再送信もできる | Must |
| F-HLT-04 | ショートカットの導入手順を説明する画面を用意する（配布用のショートカットのリンク、または作り方の手順） | Must |
| F-HLT-05 | 連携のオン・オフを設定で切り替えられる。オフのときは「ヘルスケアに送る」ボタンを表示しない | Must |
| F-HLT-06 | セッションを保存したら、ボタンを押さなくても自動でショートカットを起動する（設定で選択） | Could |

- アプリで記録を編集・削除しても、ヘルスケアには反映されません。必要な場合はヘルスケアアプリで直接修正します（画面上に注意書きを表示する）。

### 3.9 データの保存・バックアップ

| ID | 要件 | 優先度 |
|---|---|---|
| F-DATA-01 | データは端末内（ブラウザの保存領域：IndexedDB）にだけ保存する。外部のサーバーには送らない | Must |

| F-DATA-04 | バックアップファイルを読み込んでデータを復元できる。復元の前に、現在のデータが上書きされることを確認する | Must |

| F-DATA-06 | オフラインでもすべての機能を使える（ヘルスケア連携を除く） | Must |

| F-DATA-08 | 将来のクラウド同期に備え、各データに一意のID（UUID）と更新日時を持たせる。削除したデータは「削除済み」の印を付けて残す | Must |
| F-DATA-09 | 複数端末間の自動同期（クラウド同期） | Future |

### 3.10 画面サイズへの対応（レスポンシブ対応）

iPhoneでの使用を主としますが、開発中にPCで画面を確認でき、iPadでも問題なく使えるよう、画面幅に合わせて配置を切り替えます。

| 画面幅 | 想定する端末 | レイアウト |
|---|---|---|
| 768px未満 | iPhone（縦向き） | 1列表示。画面下部にタブを置く（本書の基本レイアウト） |
| 768px以上1200px未満 | iPad、iPhoneの横向き、幅の狭いPCウィンドウ | 画面左側にメニューを置く。ホーム画面などでは、人体図と記録を横に並べる2列表示にする |
| 1200px以上 | PC | 768px以上と同じ構成。中身の最大幅を決め、画面中央に表示する（横に広がりすぎないようにする） |

| ID | 要件 | 優先度 |
|---|---|---|
| F-RESP-01 | 上の表のとおり、画面幅に合わせてレイアウトを自動で切り替える。ウィンドウの幅を変えたときや端末を回転させたときも、すぐに切り替わる | Must |
| F-RESP-02 | 幅320pxから表示が崩れない（横スクロールが出ない） | Must |
| F-RESP-03 | 人体図・カレンダー・グラフは、画面幅に合わせて拡大・縮小する | Must |
| F-RESP-04 | マウスとキーボードでもすべての操作ができる（マウスを乗せたときの強調表示、Tabキーでの移動、Enterキーでの決定） | Must |
| F-RESP-05 | タッチ操作でも、ボタンなどの押せる部分は44px四方以上の大きさにする | Must |
| F-RESP-06 | iPadのSplit View（画面分割）で幅が狭くなったときも、同じルールで切り替わる | Should |
| F-RESP-07 | PCでもアプリとしてインストールし、独立したウィンドウで起動できる（ChromeとEdgeのPWAインストール機能） | Could |

## 5. 非機能要件

| 分類 | 要件 |
|---|---|
| 使いやすさ | アプリを起動してから2タップ以内でセッションを開始できる。片手で操作できる。ダークモードに対応する。iPhoneの画面上端・下端の領域（ノッチやホームバー）と表示が重ならない |
| アプリらしさ | ホーム画面に追加すると、ブラウザのアドレスバーなしの全画面で起動する。アプリのアイコンと起動画面を用意する |
| 性能 | 起動から3秒以内に操作できる状態になる。画面の切り替えやボタンの反応は1秒以内 |
| オフライン | 一度読み込んだあとは、通信がなくても起動・記録・閲覧ができる（Service Workerによるキャッシュ） |
| 更新 | 新しい版を公開したら、次回起動時に更新を知らせ、ワンタップで適用できる |
| 信頼性 | 計測中にアプリが終了してもデータが失われない（F-REC-05）。保存処理の途中で失敗した場合は保存前の状態に戻す。データ構造を変更するときは、既存データを自動で新しい形式に移行する |
| セキュリティ | HTTPSで配信する。記録データは端末内だけに保存し、外部に送信しない。外部の解析ツールや広告は組み込まない |
| 可用性 | データは端末内にあるため、サーバーの稼働率は要件として定めない（初回の読み込みと更新時のみ、配信サイトが動いている必要がある） |
| 拡張性 | 重量・回数・セット数の入力やクラウド同期に、データ構造を大きく変えずに対応できる |
| 保守性 | 計算ロジック（カロリー・回復）を画面の処理から分け、単体テストができる構造にする |

## 7. 制約事項・対象外

### 7.1 PWAであることによる制約
| 制約 | 影響と対策 |
|---|---|
| ヘルスケアに直接書き込めない | ショートカット経由で送る（3.7）。送るたびにショートカットアプリが一瞬起動する。アプリで行った編集・削除はヘルスケアに反映されない |
| iCloudで自動同期できない | バックアップファイルを手動で書き出す（3.9）。複数端末間の同期は将来対応 |
| データはブラウザの保存領域にある | **ホーム画面からアプリを削除すると、データも消える。** また、Safariのタブで開いた場合とホーム画面から開いた場合では、データの保存場所が別になる。必ずホーム画面から使うよう、初回案内で説明する |
| プッシュ通知を使わない | 終了し忘れや筋肉痛の確認は、アプリを開いたときに画面上で知らせる |
| ロック画面・ダイナミックアイランドへの表示ができない | 計測中の経過時間はアプリ内でのみ表示する |
| Apple Watchアプリは作れない | 将来、ネイティブアプリ化するときに改めて検討する |
| アプリのURLにリポジトリ名が含まれる（GitHub Pages） | **GitHubのリポジトリ名（Dev_app_training）を変更しない。** 変更するとURLが変わり、ホーム画面に追加したアプリが開けなくなる。端末内のデータも新しいURLからは読めなくなる |
| 同じドメイン（ryotasg24.github.io）のほかのサイトと保存領域を共有する | GitHub Pagesで公開するほかのリポジトリのサイトとは、ブラウザの保存領域が共有される。データの衝突を防ぐため、保存領域の名前（データベース名など）には、このアプリ専用の接頭辞を付ける |

### 7.2 対象外
- ユーザー登録・ログイン機能は作りません。
- 他人とのデータ共有、SNSへの投稿、ランキングなどの機能は対象外です。
- 消費カロリーと回復時間は推定値であり、医学的な助言ではありません。
- Androidでの動作確認は行いません（PWAのため動く可能性はありますが、対象外とします）。
